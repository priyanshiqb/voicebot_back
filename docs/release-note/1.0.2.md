# Release 1.0.2

**Released:** unreleased · **Feature:** minutes-driven plans

A plan is no longer a fixed bundle. The customer says how many minutes they need, and the
plan, the price and the credit grant are all derived from that number.

> ⚠️ **Breaking.** Two `Plan` columns are removed, one request field becomes required on
> signup, and several response fields disappear or change meaning. Every break is listed in
> Section 2, and [the migration guide](../flows/plan-v2-minutes.md) walks the whole flow
> before and after. Read it before upgrading a client.

## Section 1 — What's New

### ⏱️ Plans are sold by the minute

A plan carries a **band** — `min_minutes` to `max_minutes`, either end open — and a
**basis tier**. The customer enters the minutes they need; the server picks the one plan
whose band contains that number and computes both the price and the credit grant from it.
Bands may not overlap and may not leave a gap, so the match is a function with exactly one
answer.

📄 [Minutes-Driven Plans — What Changed, End to End](../flows/plan-v2-minutes.md)

### 💱 Money and credits now live on the same row

`wallet.CreditRate` gains `price_per_minute_inr` beside `credits_per_unit`. What a minute
of a tier costs in rupees and what it costs in credits were always two views of one
commercial decision; split across two tables they could be changed independently, and
switching a plan's basis would have doubled the credits it granted while leaving the price
untouched.

Being on `CreditRate` also means a **money price is versioned**. That table is
supersede-don't-edit, so re-pricing closes the old row and opens a new one — `base_price`
never had a history.

📄 [Plans API — How pricing is calculated](../apiDocs/onboard/plans.md)

### 🎯 One endpoint the pricing page is built on

`GET /onboard/plans/for-minutes/?minutes=1200` returns the matched plan, the full price
breakdown, the credit grant, and what that grant is worth **on each of the three tiers**.
The last part matters: "1,200 minutes" is only exact on the tier the plan is sold at, and
showing all three is what keeps the promise honest.

📄 [Plans API §for-minutes](../apiDocs/onboard/plans.md)

### 📦 Fixed-quantity packs

A plan whose band is a single value — `min == max` — sells exactly that many minutes. A
request below it is rounded **up** to the smallest pack that covers it, and the response
says so, so the page can explain rather than quietly quote a different number. Needs no
special handling anywhere: a pack is a band of width one.

📄 [Migration guide §Two ways to sell](../flows/plan-v2-minutes.md#3-step-1--configuring-a-plan-in-the-admin-console)

### 🔁 Buying more minutes is now a plan change

Asking for 1,800 minutes instead of 1,200 on the plan you already have used to be refused.
It is a real change and a real upgrade, and the existing sign test prices it without any
new concept — owes money is an upgrade, owes nothing is a downgrade scheduled to cycle end.

A downgrade in quantity moves no plan, so `Subscription.scheduled_minutes` carries it.
Without that the change would fire at cycle end having moved nothing, and the tenant would
keep paying the higher amount.

📄 [Subscription API — Change plan](../apiDocs/billing/subscription.md)

### 📊 The grant is a fact about a sale, not about a plan

`Plan.allocated_credits` answered two different questions and could only answer one once
the grant depended on a quantity. It is now `Subscription.allocated_credits` — a column,
one per sale, written from the same value handed to `wallet.grant()`, so the subscription
and the credit ledger cannot disagree about what a cycle was worth. It is also the only
place a negotiated `credit_grant` was ever visible.

### 🎚️ Thresholds and caps scale with the grant

`low_balance_percent` and `max_rollover_ratio` are read in preference to their absolute
counterparts and resolved against the cycle's own grant. The rollover one mattered most: a
fixed cap of 3,500 forfeits nothing from a 400-minute customer and **silently burns 12,500
credits** from a 2,000-minute one, at every renewal.

### 🚧 The activation gate got stricter

Eight new blocking codes, covering the ways a minutes plan can be silently unsellable — no
basis, a basis with no rate, a basis with no rupee price, a per-call basis, a free plan
open at the top, a priced plan that renews itself free, and a band that overlaps or strands
a gap. A rate edit can no longer strand a live plan's basis tier either, which was the one
door activation could not watch.

The readiness report now returns the **whole ladder** a plan is joining, with the price
either side of every boundary. A band is only correct relative to its neighbours.

📄 [Ops Plans API — Readiness](../apiDocs/ops/plans.md)

### 🛡️ Nothing in the minutes path raises on bad input

A quantity arrives from query strings, request bodies and JSON snapshots, and clients send
strings, floats, nulls and thirty-digit numbers. One coercion rule now sits in front of
every minutes-aware method: unusable input becomes "no quantity", never an exception. The
API edges refuse with a readable `400`, and a ceiling of 1,000,000 stops a mistyped number
reaching a price the amount column cannot hold.

## Section 2 — Endpoint Changes

<!--copy:start id="ep-for-minutes" label="Copy"-->
### `GET /api/v1/onboard/plans/for-minutes/` 🆕

**New endpoint.** Match a quantity of minutes to the plan that sells it, priced.

| | |
|---|---|
| Auth | **None.** This is the pricing page |
| Query | `minutes` *(int, required)* — 1 to 1,000,000 · `billing_cycle` *(string, optional)* — `monthly` (default) or `yearly` · `currency` *(string, optional)* — `INR` |

**Response `data`:**

| Field | Type | Meaning |
|---|---|---|
| `plan` | object | `id`, `code`, `name`, `description`, `billing_cycle`, `currency`, `min_minutes`, `max_minutes`, `is_fixed_quantity`, `is_most_popular` |
| `requested_minutes` | integer | What the caller asked for |
| `selected_minutes` | integer | **What is actually sold.** Send this to signup and change-plan |
| `rounded_up` | boolean | True when a pack covers a smaller request |
| `money` | object | `basis`, `price_per_minute_inr`, `gross`, `discount`, `net`, `tax`, `total`, `tax_percentage`, `currency` |
| `credits.per_minute` | integer | Credits a minute costs on the basis tier |
| `credits.granted` | integer | `selected_minutes × per_minute` |
| `credits.equivalent_minutes` | object | What the grant is worth on **each** tier, keyed by operation |
| `entitlements`, `rates` | array | As on the plan detail |

| Status | `errors` | When |
|---|---|---|
| `400` | `INVALID_MINUTES` | Missing, non-numeric, ≤ 0, or above 1,000,000 |
| `404` | `NO_PLAN_FOR_MINUTES` | Nothing covers it. `data` carries `below` and `above` — the nearest bands |
| `409` | `PLAN_NOT_SELLABLE` | The ladder matched a plan the catalogue cannot price — a configuration fault |

**Client action:** use `selected_minutes`, never `requested_minutes`, for anything that
charges. On `rounded_up`, tell the customer which pack covers them.

### `GET /api/v1/onboard/plans/` · `GET /api/v1/onboard/plans/{id}/`

**Change:** new fields, two removals, and four fields whose meaning changed.

| | |
|---|---|
| Request | *unchanged* |
| New response fields | `min_minutes` *(int \| null)* · `max_minutes` *(int \| null)* · `credit_basis` *(string \| null)* · `is_minutes_based` *(boolean)* · `is_fixed_quantity` *(boolean)* · `rates[].price_per_minute_inr` *(string \| null)* · `rates[].is_basis` *(boolean)* |
| **Removed** | `base_price` · `allocated_credits` |

fields only for a "from ₹X" label; to charge, quote the real quantity through
`for-minutes/`. `GET /onboard/plans/dropdown/` is unchanged in shape — its label now shows
the entry price.

### `GET /api/v1/onboard/billing-breakdown/` 🆕

**New endpoint.** The registrant's price for their chosen plan and minutes, fetched again on
demand — for a page that has been refreshed.

| | |
|---|---|
| Auth | Temp token — `Authorization: Bearer <temporary_token>` |
| Request | No body, no query parameters |

**Response `data`:**

| Field | Type | Meaning |
|---|---|---|
| `plan` | object | `id`, `name`, `code`, `billing_cycle`, `currency`, `min_minutes`, `max_minutes`, `is_fixed_quantity`, `is_minutes_based` |
| `selected_minutes` | integer \| null | The quantity chosen |
| `billing_breakdown` | object | Identical to `verify-otp/` |
| `sellable` | boolean | Whether `create-order-just-in-time/` would accept this selection |
| `reason` | string \| null | Why not, when `sellable` is `false` |

| Status | `errors` | When |
|---|---|---|
| `400` | `PLAN_SELECTION_REQUIRED` | The registration has no plan |
| `401` / `403` | — | Missing, expired or non-temp token |

**Client action:** call on page load to restore the pricing summary. Unlike
`resume-session-token/` it has no side effects — it neither reissues the token nor works out
the next step — so it is safe on every render. Treat `sellable: false` as "ask for a new
quantity": checkout would refuse with `MINUTES_NOT_SELLABLE`.

### `PATCH /api/v1/onboard/update-plan/`

**Change:** optional `minutes`, re-validated against the plan being switched to.

| | |
|---|---|
| New request field | `minutes` *(int, optional)* — omitted, the current quantity is kept and re-checked |

### `POST /api/v1/billing/subscription/change-plan/`

**Change:** optional `minutes`, and a request that was previously always refused is now
valid.

| | |
|---|---|
| New request field | `minutes` *(int, optional)* — omitted, the current quantity is carried across and resolved into the new plan's band |
| New response field | `selected_minutes` *(int \| null)* on the scheduled and immediate-free payloads |
| Changed `409` | `PLAN_UNCHANGED` now fires only when **both** the plan and the quantity are unchanged |

| Request | Outcome |
|---|---|
| Different plan, no `minutes` | Current quantity resolved into the new band; a pack resolves to its one value |
| Different plan, with `minutes` | Validated against the new band |
| **Same plan, different `minutes`** | 🆕 A real change — upgrade if it costs more, scheduled downgrade if less |
| Same plan, same `minutes` | `409 PLAN_UNCHANGED` |

**Client action:** offer a "change my minutes" control. `DELETE
/billing/subscription/scheduled-change/` clears the scheduled quantity along with the plan.

<!--copy:start id="ep-ops-rates" label="Copy"-->
### `PUT /api/v1/ops/plans/{id}/rates/`

**Change:** each rate row carries a rupee price, and a write can now be refused.

| | |
|---|---|
| New request field | `rates[].price_per_minute_inr` *(decimal(10,4) \| null, optional)* — **required on the tier named by `credit_basis`** |
| New response field | The same, on every returned rate row |
| New status | **`409`** — `RATE_WOULD_STRAND_BASIS`, with a sentence naming the tier |

A live plan reads both its price and its grant from one rate row. Blanking that row's
rupee price, or making it `per_event`, would break a plan already on sale — so it is
refused. Drafts are exempt: being incomplete is what a draft is for.

**Client action:** always send `price_per_minute_inr` back when echoing a rate card, or the
write will be refused.

### `POST /api/v1/ops/plans/{id}/activate/` · `GET /api/v1/ops/plans/{id}/readiness/`

**Change:** eight new blocking codes, three new warnings, one warning removed, and a new
report block.

| New blocking code | Meaning |
|---|---|
| `CREDIT_BASIS_UNSET` | No basis tier — nothing to price or grant from |
| `CREDIT_BASIS_RATE_MISSING` | The basis tier has no open rate row |
| `CREDIT_BASIS_NO_INR_PRICE` | The basis row has no rupees-per-minute price |
| `CREDIT_BASIS_PER_EVENT` | A per-call basis has no per-minute meaning |
| `FREE_MINUTES_PLAN_UNCAPPED` | Free per minute with no ceiling — unbounded free credits |
| `RENEWS_FREE_BUT_PRICED` | A priced plan that renews itself would stop billing |
| `BAND_OVERLAPS` | Another active plan sells the same quantities |
| `BAND_GAP` | A gap to the next ranged band |

**New warnings:** `RUPEES_PER_CREDIT_INCONSISTENT`, `RATE_MISSING_INR_PRICE`,
`LADDER_OPEN_BOTTOM_MISSING`, `LADDER_OPEN_TOP_MISSING`.
**Removed warning:** `PAID_PLAN_NO_CREDITS` — now refused outright rather than noted.

`readiness/` gains a `ladder` object: `bands[]` (every band in this plan's cycle, with
`is_this_plan`), `boundaries[]` (`at_minutes`, `price_below`, `next_minutes`,
`price_above`, `cheaper_above`) and `warnings[]`.

> `cheaper_above` is **information, not a fault**. Every volume ladder is cheaper just past
> a boundary — that is the discount. Render the numbers; do not flag them.

## Behaviour changes that alter no signature

| Area | Change |
|---|---|
| Activation | The paid quantity is applied **verbatim**. If a band moves between the order and the payment clearing, the customer still gets what they paid for |
| Renewal | Priced and granted from the stored quantity at **today's** basis rate — the one place a rate change reaches an existing customer |
| Wallet alert | Stamped from `low_balance_percent` of this cycle's grant when set, instead of the plan's absolute figure |
| Rollover cap | Resolved from `max_rollover_ratio` × this cycle's grant when set |
| Free signup | Now runs the shared promotion; `transaction.tenant` is set and the registrant's locale survives |
| Query budget | `GET /onboard/plans/` and `eligible-plans/` prefetch the rate card — one query for the catalogue, not one per plan |
| OpenAPI schema | `billing_breakdown` in the schema for `verify-otp/`, `update-plan/`, `resume-session/` and `resume-session-token/` now declares `selected_minutes`, `price_per_minute_inr` and `allocated_credits`, and the resume schema declares top-level `selected_minutes`. The responses already carried them; the schema did not, so a client generated from it was missing the fields |

## No longer possible

| | |
|---|---|
| **A plan that grants nothing** | The grant is `minutes × credits-per-minute`, both positive. Pay-as-you-go is now an activation decision — `credit_grant=0`, the same override a negotiated contract uses |
| **A plan with no basis tier** | No price and no grant. Activation refuses it; migration `0035` retires any that were already active. Existing subscriptions on one keep working and can move away at any time |

## Migrations

| Migration | Contents |
|---|---|
| `wallet.0006_creditrate_price_per_minute_inr` | One nullable column |
| `onboard.0030_plan_credit_basis_…` | Band and basis on `Plan`; `selected_minutes` and `allocated_credits` on `Subscription`; `selected_minutes` on `TempUser`; `ck_plan_minutes_band_valid` |
| `onboard.0031_backfill_subscription_allocated_credits` | **Data.** Copies each subscription's grant onto its own row, from its snapshot or its plan |
| `onboard.0032_subscription_scheduled_minutes` | One nullable column |
| `onboard.0033_plan_low_balance_percent_…` | The two calibration fields |
| `onboard.0034_remove_plan_…zero_cost_and_more` | Drops `base_price` and its check constraint |
| `onboard.0035_retire_plans_without_a_basis` | **Data.** Retires any active plan with no basis; fills remaining null grants |
| `onboard.0036_remove_plan_allocated_credits_and_more` | Drops `Plan.allocated_credits`; makes `Subscription.allocated_credits` non-null |

**Order matters.** `0031` reads `Plan.allocated_credits` while it still exists, and `0035`
retires unsellable plans before `0036` removes the last column they could have been priced
from. Run them in sequence; there is no downtime and no rewrite of any `plan_snapshot` —
those are frozen contracts and are only read.

## Seed data

`json_files/plan_v2.json`, `plan_entitlement_v2.json` and `credit_rate_v2.json` carry a
placeholder ladder — Starter (–500), Growth (501–2,000), Scale (2,001–) and a yearly plan —
all added to `all.json`. **The numbers are placeholders**; real plans are created from the
admin console.

`json_files/plan.json` now seeds its five original plans as **retired**: they have no basis
tier, so they cannot be priced or granted from. They are kept so existing subscriptions
still resolve their plan.
